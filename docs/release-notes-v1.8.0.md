# 1.8.0 — 正文与回合隔离、可复现升级门槛

## 修复

- 最终答复和普通通知不再被工具进度识别器按正文外形删除；移除中文/emoji 短行加围栏的结构猜测。无法确认的预览保留，不用空白替代正文。
- 工具、推理、用量及结束事件只认精确身份。未知事件不再借用唯一活动飞书回合；任务路由使用无进程环境变量回落的 `bound_session_env`。
- 同一会话连续两问通过入站 message_id 区分最终答复，后一问无预览也不覆盖旧卡。
- 独立通知不合并到活动答复卡，不更改答复的映射和展示状态；新旧回合显示状态按 turn_id 分开。
- 新 admission 清理旧 session 绑定，拒绝旧回合迟到事件。
- 纳入此前本地已验收的单卡最终投递、更新失败保留原卡重试、动态内容标题、折叠工具单代码块。
- 标题不附工具次数/耗时，这两项仅在尾部加粗。

## 可复现验证

- `tests/run_all.py` 在临时 Profile 和插件副本中执行所有 `check_*.py`，不会读写本地实际配置及检查点。
- `LCH_HERMES_DIR` 可指向未打补丁的官方 Hermes 源码；测试使用真实 Python 依赖，飞书网络由测试 FakeRest 隔离。
- GitHub Actions 矩阵：官方 Hermes v0.23.3 / v0.23.4 × lark-oapi 1.6.8 / 1.7.5，Python 3.14。每项执行完整行为检查与官方插件 validate，并验证 Hermes checkout 未被修改。
- 本版本的本地复现与 CI 结果以发布说明中链接的精确提交为准。不能从版本范围推断未来版本已兼容。

## 边界

- 仍然是 Hermes 平台插件，不安装 HFC sidecar、不向 Hermes 源文件注入补丁。
- 仍依赖内置适配器、最终投递入口、任务上下文和 SDK 的内部契约；官方 validate 的 private-import / SDK 动态代码提示如实保留。
- 这些门槛不是完整 Hermes 安装、模型调用或真实飞书客户端视觉/按钮认证。完整官方依赖安装在本地曾遇 Pillow 约束冲突，因此兼容门槛只安装插件测试所需真实依赖。
- 本地源码同步不等于运行网关已加载；需要获授权后重启网关才能加载新版本。已有卡片不会自动迁移。
